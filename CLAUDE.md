# CLAUDE.md - Panaversity Hackathon Guidelines

This document outlines the interaction and development protocols for the project, following the CLAUDE model.

## C - Clarity
- All specifications and tasks must be clearly defined before implementation begins.
- Code must be self-documenting where possible, with comments reserved for complex logic.

## L - Lean
- Adhere to the principle of building the simplest thing that works.
- Avoid over-engineering. Focus on the core requirements of the current phase.

## A - Atomic
- Commits and tasks should be atomic, representing a single, complete unit of work.

## U - Unambiguous
- Requirements in `speckit.specify` must be testable and unambiguous.

## D - Documented
- All significant architectural decisions are recorded in `speckit.plan`.
- The project's purpose and standards are defined in the `speckit.constitution`.

## E - Evolving
- The spec files are living documents and can be updated to reflect new understandings, but only after consensus.
